# TENET

*Ten tenets of minimal, spec-driven design. No code. No process. Just text.*

1. The specification is never the source of truth — only source code is.

2. One up-to-date README.md will always beat dozens of obsolete specs.

3. A code repository is not an issue-tracking system.

4. Source code is not a place for discussions.

5. If you cannot describe a new feature in five sentences, you will fail — no exceptions.

6. If you cannot describe the implementation design in five sentences, you will fail — no exceptions.

7. Fit the framework and tools to your project, not your project to the framework. You own your code.

8. Never grant an AI agent permission to modify production infrastructure — no exceptions.

9. Always do a code review and manual testing before merging a PR. You defined the feature, so you must validate it.

10. An AI agent can hallucinate and fail — there is no "best model".

7. Passe Framework und Tools an dein Projekt an, nicht dein Projekt an das Framework. Dein Code gehört dir.

8. Gib einem KI-Agenten niemals die Berechtigung, die Produktionsinfrastruktur zu ändern — keine Ausnahmen.

9. Mache vor jedem PR-Merge immer ein Code-Review und manuelle Tests. Du hast das Feature definiert, also musst du es validieren.

10. Ein KI-Agent kann halluzinieren und scheitern — es gibt kein „bestes Modell“.

3. Un repositorio de código no es un sistema de seguimiento de incidencias.

4. El código fuente no es un lugar para discusiones.

6. Si no puedes describir el diseño de la implementación en cinco frases, fracasarás — sin excepciones.

7. Adapta el framework y las herramientas a tu proyecto, no tu proyecto al framework. El código es tuyo.

8. Nunca concedas a un agente de IA permisos para modificar la infraestructura de producción — sin excepciones.

9. Haz siempre revisión de código y pruebas manuales antes de fusionar un PR. Tú definiste la funcionalidad, así que debes validarla.

10. Un agente de IA puede alucinar y fallar — no existe el «mejor modelo».
